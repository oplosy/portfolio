# Portfolio Scrollcraft Brief

Status: authored from the user's supplied brief. No external reference sites are included.

## 1. Vibe and references

User language: modern, high-quality, visually strong, Awwwards-style, cinematic, technically deep, backend and infrastructure focused.

The visual world is Living Infrastructure: architectural, controlled, spatial, and precise. It explicitly avoids hacker, cyberpunk, matrix, fake-terminal, generic glass, and generic SaaS language.

## 2. Scroll journey

`NODE -> SYSTEM -> ARCHITECTURE -> PROJECT -> INFRASTRUCTURE -> NODE`

First prototype: Identity -> System identity -> About focus -> Projects topology.

Later journey: Project detail -> Technology layers -> Experience axis -> Contact convergence.

## 3. Energy curve

- Identity: controlled and quiet.
- System opening: increasing energy and density.
- About: lower energy and stable reading.
- Projects morph: highest energy and largest spatial change.
- Later architecture: confident and analytical.
- Contact: quiet resolution.

## 4. Feeling curve and peak

| Act | Intended feeling | On-screen cause |
| --- | --- | --- |
| Identity | Orientation | One stable root node, name, and backend role |
| Opening | Curiosity | The node shell separates and exposes internal layers |
| Topology | Comprehension | Routes connect services, queue, cache, and data |
| About | Recognition | One real node becomes a calm reading surface |
| Projects | Awe | The same topology physically reorganizes into project modules |
| Focus | Confidence | One project gains depth while its architecture remains connected |

Peak sentence: "The single node opened into a complete backend system, then the system became the projects without the scene ever cutting."

Peak location: Projects transformation.

## 5. Signature move

The living request trace persists through the whole page. It enters the root node, travels through the system, exposes the About layer, and becomes the selected project's focus and architecture path. It also acts as positional navigation.

## 6. Aesthetic range

Far from premium-minimal. The composition is experimental, spatial, and high-motion, but all complexity belongs to one visual system. The palette and typography remain disciplined so the system does not become decorative noise.

## 7. Structural choice

One unbroken world. Implementation uses a single fixed SVG stage and one scroll spacer. Copy lives in semantic fixed windows. There are no section blocks that pin, unpin, and slide past the stage.

## 8. Existing assets

No complex assets are required for the first prototype. Use semantic HTML, CSS, SVG primitives, and GSAP. Real project imagery and any 3D assets are deferred until the scroll choreography is approved.

## Visitor and outcome

Primary audience assumption: technical recruiters, engineering leaders, founders, and collaborators assessing backend and infrastructure capability.

Belief installed by the end: this engineer can reason about complex systems and turn that reasoning into reliable architecture.

Primary action: `Contact`.

## Tell-someone sentence

"It's the site where one node unfolds into a living backend system and becomes the developer's projects."

## Authored silence

The About reading interval deliberately reduces route motion and visual density before the Projects peak. This is not dead scroll; it is the quiet interval that gives the peak contrast.

## Prototype boundary

Implement only Hero -> About -> Projects after this direction is accepted. Do not build Skills, Experience, Contact, or full project detail in the first prototype.
